Этот файл — точка входа. Открой репо `foto-klass` в Claude Code и в самой
первой реплике агенту просто скажи:

> Прочитай `docs/virtus-onboarding.md` и сделай Setup (Шаг 1). Дай отчёт.

Дальше Claude Code сам всё развернёт. Ниже — что он будет делать и какие
команды ты будешь давать ему потом.

## Шаг 1 — Setup (агент выполняет один раз)

Цель: получить рабочее окружение и убедиться что пайплайн запускается на
эталонных 7 фото в `sample/`.

Агент делает по порядку (с проверкой и логированием):

1. Создаёт venv с Python 3.11:
   ```bash
   python3.11 -m venv .venv
   source .venv/bin/activate
   pip install --upgrade pip
   ```
2. Ставит зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Скачивает веса апскейлера Nomos PLKSR (~190 MB):
   ```bash
   mkdir -p weights
   huggingface-cli download Phips/4xNomosWebPhoto_RealPLKSR \
       4xNomosWebPhoto_RealPLKSR.safetensors --local-dir weights
   ```
4. Прогоняет 7 эталонных фото через быстрый режим:
   ```bash
   python prototype.py --input sample/ --output output/ --mode resize
   ```
   На Mac MPS это ~30 секунд после прогрева моделей. На первом запуске
   ещё ~2 GB качается из Hugging Face (Florence-2 + BiRefNet) — это норма.

5. Открывает все 7 итоговых `output/*.webp` и оценивает:
   - есть ли деталь в кадре, занимает ~85% по большей стороне
   - белый ли фон
   - читаются ли артикулы на схемах (308014, 308044, 313374 и т.п.)

6. Отчитывается одним сообщением: что прошло, что упало (если упало),
   среднее время на фото из `output/summary.json`.

После этого окружение готово. Дальнейшие команды — ниже.

## Что важно знать про пайплайн

Полный контекст — в `CLAUDE.md` и `RUNBOOK.md` (оба читай). Кратко:

- Два режима: **`--mode resize`** (быстрый, для массового прогона 13M, водяные
  знаки остаются) и **`--mode full`** (медленный, чистит фон+вотермарки,
  только для отборных фото на Google Merchant).
- Зафиксированный апскейлер — **Nomos PLKSR** (выбран после сравнения с
  DAT2, Real-ESRGAN, HAT-L и iloveimg.com).
- Кэш: повторный запуск автоматически пропускает уже обработанные фото
  по SHA256. `--force` чтобы перепрогнать.
- На Mac полная ветка медленная (~50-75с/фото) — это норма: BiRefNet
  работает на CPU потому что `torchvision.ops.deform_conv2d` не реализован
  для MPS. На RTX 4090 в 10-20 раз быстрее.

## Типовые задачи (промпты которые ты пишешь Claude Code)

### 1. Локальный прогон папки

```
Прогон папки ~/Downloads/batch-01/ через prototype.py в режиме resize.
Output в output_batch-01/. После — покажи summary.json и открой 3-4 случайных
результата, опиши что увидел.
```

### 2. Что-то поломалось / нашёл странный результат

```
В output_xxx/ есть фото с review_reason. Перечисли их.
Для одного из них — открой все debug/*.png и metrics.json,
объясни почему пайплайн отправил в review.
```

### 3. Прогон на RunPod (большой батч)

```
Цель: прогнать ~5000 фото на RunPod RTX 4090 через --mode resize.

Шаги:
1. Подними RunPod community RTX 4090 pod (выбери самый дешёвый, ~$0.34/час)
2. Через SSH в pod:
   - склонь git@github.com:Allzap/foto-klass.git
   - venv + requirements.txt
   - скачай Nomos weights
3. Перешли в pod фото (rsync с моей машины или скачай из Hetzner S3,
   если HETZNER_S3_* прописаны в .env)
4. Запусти prototype.py --device cuda --mode resize
5. Скачай результаты обратно
6. ОБЯЗАТЕЛЬНО останови pod после окончания (иначе $)

Дай отчёт: реальная скорость на 4090, средняя цена за фото, всё что упало.
```

### 4. Сравнить качество с эталоном

```
Сравни output/3_orig.webp (наш результат) с sample/3_orig_ilove.jpg
(результат iloveimg.com). Открой оба, оцени:
- читаемость текста на наклейке детали ("AL-KO" + мелкие строки артикула)
- общий вид металла
- видимость watermark по фону
```

## Что ты НЕ должен делать без спроса у vda

Полный список в `CLAUDE.md`. Самое важное:

- Не пушить force-push в main, не переписывать историю
- Не коммитить `*.pth`, `*.safetensors`, содержимое `output*/`, `weights/`,
  `.env*` (в .gitignore — проверь перед коммитом)
- Не менять выбор моделей в `requirements.txt` без обсуждения с vda
- Не разворачивать ничего на сервер `135.181.148.66` без явного "поехали"
